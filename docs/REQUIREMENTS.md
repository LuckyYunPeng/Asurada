# Asurada 产品需求（已定范围）

> 原名 **CommitDock**，对外展示名与产品名均为 **Asurada**。  
> 开源仓库：<https://github.com/LuckyYunPeng/asurada> · 协议 **MIT**

## 一句话

macOS 边缘吸附小标签 + 浮层面板：管理多个本地 git 仓库，验收后一键用本机 `pi --print` 生成**中文 Conventional Commit** 并**无确认**执行 `git add -A && git commit && git push`。

## 目标用户

- 在 macOS 上同时验收 / 维护多个本地 git 仓库的开发者（Agent 辅助写代码、自测节奏快）。
- 希望 **commit 与 push 不占用主 Agent 对话上下文**，又不想为每次提交单独开一场聊天的人。
- 本机已安装 **`pi`（agent CLI）** 与 **`git`**，并接受「一键直推远端、不再二次确认」的产品立场。

## 平台

- **macOS 优先**（当前唯一目标平台；无 Windows / Linux 产品承诺）。
- 分发形态：`.app` / `.dmg`（CI 产出；见 README 安装说明）。

## 核心用户流程

### 1. 边缘 tag → 浮层面板

- 屏幕边缘常驻 **小 tag**（品牌 logo + 短标记）；点击 **展开 / 收起** 浮层面板。
- 面板宽度约 **320–360pt**，内容过高时 **内部滚动**；与 tag 同侧贴边（产品目标；见交接文档中的工程现状）。
- tag 在面板收起且存在 **未读失败** 时显示 **小红点** 提示。

### 2. 项目管理

- **添加项目**：选择本地文件夹路径（须为有效目录）；持久化到应用数据目录。
- **移除项目**：从列表删除（不删磁盘仓库）。
- 每行展示：**显示名**、**短路径**（中间省略、保留末两段）、**工作区状态**、主操作按钮。

### 3. 一键「提交并推送」（产品按钮文案）

对 **有未提交变更** 的行：

1. 在该项目目录非交互执行：`pi --print '<固化提示词>'`  
   - 提示词要求：根据 `git status` / `git diff` 生成 **Conventional Commits** 一行标题；**type 英文**（feat/fix/chore/docs 等），**冒号后简体中文**；只输出一行，无引号、无 Markdown。
2. 无用户确认地执行：`git add -A && git commit -m '<消息>' && git push`
3. 回写 UI：**Toast** + 行内结果（成功：`已推送 · …`；失败：原因可辨）。

**术语约定（协作必读）**：界面与文档中的 **「提交并推送」** 指上述 **add + commit + push 整链**；口语里的「只提交不推远程」**不是**本产品主按钮语义。

### 4. 首次打开：引导 → 预检 → 列表

| 阶段 | 行为 |
|------|------|
| **三步引导** | 说明使用场景；可 **跳过**；设置内可 **重看引导** |
| **本机预检** | 检查 `pi` 在 PATH、`pi --print` 非交互可用（超时约 12s）、`git` 可调用；未通过则阻断主流程并允许 **重新检查** |
| **项目列表** | 预检通过后加载持久化项目；空列表引导 **添加项目** |

打开面板且引导已完成时，应触发 / 刷新预检（与列表并列门禁）。

### 5. 工作区干净

- `git status --porcelain` 为空：**主按钮禁用**，状态文案 **「无变更」**（或等价「工作区干净」），**不调用 `pi`**。

### 6. 风险明示与反馈

- 列表非空时，面板内 **常驻风险条**（非 modal）：明示会 **暂存、提交并推送到远端，且不再确认**。
- **Toast**：提交成功 / 失败的全局轻提示。
- 行内：进行中（「提交中…」、防重复点击）、成功、失败摘要；失败时 tag 可带未读点。

## 非目标（明确不做）

- **Apple 代码签名与公证**：产品范围外后置；不阻塞当前未签名 CI 产物（见 README）。
- **其它产品线**：不做 PR/MR 创建、冲突解决向导、完整 git GUI、Windows/Linux 客户端。
- **交互式 `pi` 会话**：提交路径仅 `pi --print`，不对话确认 commit 内容。
- **仅 commit 不 push** 作为一等公民流程（若未来需要，另开需求，不改变当前「提交并推送」定义）。
